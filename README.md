# EatGood（吃好）

**用心吃好。**

EatGood 是一个长期了解用户的个人饮食伙伴，结合饮食偏好、日常习惯、地区与时令，帮助用户决定今天吃什么、发现喜欢的食物，并通过「跟我一起做」完成一顿饭。

## V1.0 产品结构

| 一级入口 | 用户目标 |
|---|---|
| 首页 | 今天吃什么？ |
| 探索 | 还有什么好吃的？ |
| 跟我做 | 这道菜具体怎么做好？ |
| 我的 | 吃好越来越了解我。 |

核心闭环：

`首次认识用户 → 饮食画像 → 推荐 → 食材 / 菜谱 → 决定吃 → 跟我一起做 → 完成 → 反馈 → 更新画像 → 下一次推荐`

探索闭环：

`主动探索 → 食材 / 口味 / 菜系 / 做法 / 时令 → 发现新菜 → 探索记录去重 → 点亮菜单地图`

## 开发顺序与架构方向

按定稿中的 Phase 0–7 推进：产品定义、数据工程、基础服务、核心 App、推荐系统、菜单地图、Cooking Engine、完整闭环测试。

正式开发 UI 前先确定数据模型，并建设可维护结构化内容的 CMS。个人开发先贯通「选择牛肉 → 记录偏好 → 推荐土豆炖牛肉 → 菜谱 / 食材 → 想吃 → 跟做 → 完成 → 反馈 → 调整推荐」这一条纵向链路，再拓宽内容和模块。

移动端优先，定稿建议采用 Flutter、Go、PostgreSQL、Redis 和模块化单体服务；全文搜索保留 Meilisearch / Typesense 的可选方向。具体工程设计以定稿为基础细化，不把建议直接写成已完成的技术选型。

推荐以规则、偏好权重、内容标签和行为反馈为基础。AI 辅助搜索解析、推荐解释和内容整理；食材知识、用户忌口、菜谱核心步骤和推荐约束以结构化数据为准。

## 内容与发布目标

- 建议内容目标：500～800 个常用食材、1000～1500 道结构化菜谱、100～200 道精品 Cooking Mode 菜谱。
- 发布验收包括：60 秒内完成首次画像初始化、合理的多维搜索、食材基础与时令信息、正式菜谱结构化、至少 100 道完整 Cooking Mode 菜谱、探索记录不重复计数、用户数据跨设备同步。
- 推荐验收原文及完整发布标准见定稿第三十二章；指标定义在工程验收方案中细化，保留原文阈值与适用范围。
- 首版不做社区、外卖平台、生鲜电商或医疗诊疗；营养信息不主导普通首页。
- 「吃好+」及未来权益按定稿第二十四章区分，会员基础设施可以先建设，未来权益不自动计入 V1.0。
